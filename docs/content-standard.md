# 数学コンテンツ作成基準

この文書は、Math-OS に収録する各概念・各単元の品質基準を定める。全項目を機械的に埋めるのではなく、概念の性質に応じて必要な要素を選ぶ。

## 1. 概念ページの基本構成

1. **問い・動機** — 何を扱うのか。どんな困りごとや数学的要求から生まれるのか。
2. **直観・意味** — 具体例、図、操作などを通して対象の意味をつかむ。
3. **定義** — 対象を曖昧さなく定める。用語・記号・量化範囲を明確にする。
4. **性質** — 定義から従う重要な性質を整理する。
5. **導出・証明** — 公式や定理がなぜ成立するかを、前提から追える形で示す。
6. **表現・可視化** — 式、図、グラフ、表、数直線、動的操作などを使う。
7. **条件・限界** — 成立条件、定義域、例外、誤りやすい一般化を明示する。
8. **例・基本演習** — 意味確認、基本操作、逆向きの推論、基本的な接続・応用を確認する。
9. **関連概念** — 前提・発展・応用・表現変換などのリンクを示す。

概念によっては、定義が先に必要なもの、具体例から入る方がよいもの、可視化が本質的でないものがある。順序と構成は固定しない。

## 2. 説明の品質

- 用語を導入する前に、必要な既知事項を確認する。
- 「明らか」「同様に」などで重要な論理を飛ばさない。
- 記号の意味と、式変形で保たれるもの・変わるものを説明する。
- 直観と厳密な定義を混同しない。直観は入口、定義は数学的な基準として扱う。
- 定理の逆が成り立つかどうかを必要に応じて区別する。
- 同値変形と一方向の含意を区別する。
- 計算手順だけでなく、その操作が許される理由を説明する。
- 複数の説明を並べる場合、それぞれが何を見やすくするのかを示す。

## 3. 演習設計

基礎段階の演習は、難問化ではなく理解の検証を目的とする。

推奨する問いの型：
- 意味確認：定義や表現を正しく読み取れるか。
- 基本操作：定義・性質に沿って計算や変形ができるか。
- 逆向き：結果から条件や元の対象を考えられるか。
- 表現変換：式・図・グラフ・言葉を行き来できるか。
- 条件判断：どの条件で性質が使えるかを判断できるか。
- 接続：既習概念との基本的な関係を使えるか。

各演習には、確認したい理解・技能を対応づける。単に問題数を増やさない。

## 4. 可視化・インタラクション

可視化は装飾ではなく、数学的関係を観察・操作するために使う。

例：
- 関数：係数や入力を変え、グラフの変化を観察する。
- 三角関数：単位円上の点とグラフを対応させる。
- 図形と方程式：図形条件と座標・方程式を連動させる。
- 数列：項番号と項の値の対応、規則の変化を観察する。
- 確率：試行を繰り返し、理論値と相対度数を比較する。
- 微分：割線の傾きから接線の傾きへの変化を観察する。

可視化だけで証明・定義の代用をしない。操作で観察した事実と、数学的に証明された事実を区別する。

## 5. 誤り・つまずきの扱い

誤答を単なる不注意として片付けず、誤った推論がどこで生じたかを示す。特に以下を確認する。

- 定義域・条件の見落とし
- 逆・裏・対偶の混同
- 同値でない変形
- 表現の意味の取り違え
- 具体例から一般化しすぎること
- 記号操作の対象や範囲の混同
